# Working guidance

- Inspect the workspace before changing it; follow the project's existing conventions.
- Make the smallest change that satisfies the request, then verify it with the project's own checks.
- Prefer deterministic scripts under `scripts/` for repeated mechanical steps.
- Keep final artifacts at the paths the task asks for; do not stop at describing them.
- If a check fails, read the error and fix the cause instead of repeating the same command.
